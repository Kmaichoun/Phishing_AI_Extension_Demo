# โครงบทความ Phish Radar สำหรับผู้เขียน

สถานะ: แบบโครงให้เพื่อนเขียนเอง ยังไม่มีเนื้อหาบทความ ช่อง `[ผู้เขียนเติม]` เป็นงานที่ต้องทำก่อนส่ง ใช้คู่กับ [คู่มือเขียน](WRITING_GUIDE_TH.md), [ข้อเท็จจริง](PROJECT_FACTS_TH.md) และ [เอกสารอ้างอิง](REFERENCES_TH.md)

ผู้เขียนและรหัสนิสิตหรือนักศึกษา: [ผู้เขียนเติม]

## บทคัดย่อ

[ผู้เขียนเติม: ปัญหาและวัตถุประสงค์ วิธีดำเนินงาน ขอบเขตการทดสอบ ผลสำคัญที่มีหลักฐาน และข้อสรุป เขียนส่วนนี้หลังส่วนอื่นเสร็จ]

คำสำคัญ: [ผู้เขียนเลือกคำที่ตรงกับเนื้อหาและจำนวนที่แม่แบบกำหนด]

## 1 บทนำ

### 1.1 ที่มาและความสำคัญของปัญหา

[ผู้เขียนเติม พร้อมอ้างอิง หากใช้สถิติให้ระบุช่วงเวลาและแหล่งต้นทาง]

### 1.2 วัตถุประสงค์

[ผู้เขียนเติมวัตถุประสงค์ที่ตรวจสอบจากผลงานและการทดสอบได้]

### 1.3 ขอบเขตของโครงงาน

[ผู้เขียนเติม: Web App, Chrome Extension, Backend, การประเมินจาก URL, บทบาท LLM และข้อจำกัดของระบบทดลอง]

### 1.4 ประโยชน์ที่คาดว่าจะได้รับ

[ผู้เขียนเติมตามขอบเขต หลีกเลี่ยงการรับประกันความปลอดภัยหรือผลที่ยังไม่ได้วัด]

## 2 ทฤษฎีและงานวิจัยที่เกี่ยวข้อง

### 2.1 ฟิชชิงและการประเมินจาก URL

[ผู้เขียนเติมความหมาย ลักษณะข้อมูล และข้อจำกัดของการตรวจจาก URL ใช้ R3 ประกอบตามความเหมาะสม]

### 2.2 Random Forest และคุณลักษณะของ URL

[ผู้เขียนเติมหลักการจาก R1 และอธิบายความสัมพันธ์กับคุณลักษณะของรุ่นที่ใช้จริง]

### 2.3 การปรับค่าความน่าจะเป็นและเกณฑ์ตัดสิน

[ผู้เขียนเติมแนวคิดจาก R2 แยกหลักการ calibration ออกจากการเลือก Warning และ Blocking ของโครงงาน]

### 2.4 การประเมินผลและคุณภาพข้อมูล

[ผู้เขียนเติม TP FP TN FN, Precision, Recall, FPR และ PR analysis ตาม R4 และ R5 อธิบายเรื่องข้อมูลซ้ำ leakage และการแยกโดเมน]

## 3 วิธีการดำเนินงาน

### 3.1 ความต้องการและสถาปัตยกรรมระบบ

[ผู้เขียนเติม พร้อมแผนภาพ Web หรือ Extension → Backend → โมเดล และเส้นทาง Database กับ LLM]

### 3.2 ข้อมูลและการเตรียมข้อมูล

[ผู้เขียนเติมชื่อและรุ่นข้อมูล ที่มา label จำนวนแต่ละ class การจัดการข้อมูลซ้ำ และวิธีแยก train calibration validation กับชุดยืนยัน]

### 3.3 การสกัดคุณลักษณะและรุ่นโมเดล

[ผู้เขียนเติมชื่อ artifact, SHA256, schema, จำนวนคุณลักษณะ และขั้นตอนที่ทำจริงจากหลักฐาน ห้ามนำวิธีฝึกของคนละรุ่นมารวมกัน]

### 3.4 การคำนวณคะแนนและการแจ้งเตือน

[ผู้เขียนเติมสมการและคำอธิบายตัวแปร แหล่งคะแนนหลัก การใช้เกณฑ์ การปัดเศษ และกรณี backend ใช้งานไม่ได้]

### 3.5 การอธิบายผลและการจัดเก็บข้อมูล

[ผู้เขียนเติมบทบาท LLM, ขอบเขต Privacy Mode, ฐานข้อมูล และเส้นทางประวัติการตรวจตาม source รุ่นที่รายงาน]

### 3.6 แผนทดสอบ

[ผู้เขียนเติมรุ่นระบบและสภาพแวดล้อมที่จะทดสอบ ขั้นตอนและเกณฑ์ผ่านของแต่ละฟังก์ชัน ชุดข้อมูลและตัวชี้วัดของโมเดล แยกผลใช้งานระบบออกจากผลโมเดล]

## 4 ผลการดำเนินงาน

### 4.1 ผลการพัฒนาระบบ

[ผู้เขียนเติมภาพหน้าจอที่เก็บจริง พร้อมหมายเลขภาพ คำอธิบาย และวันที่ทดสอบ]

| [ผู้เขียนเติม] | [ผู้เขียนเติม] | [ผู้เขียนเติม] | [ผู้เขียนเติม] | ยังไม่ทดสอบ |

### 4.3 ผลประเมินโมเดล

[ผู้เขียนเติมชื่อรุ่น hash ชุดข้อมูลและบทบาทของชุดนั้น จำนวนแต่ละ class และ threshold ทุกครั้งที่แสดงตาราง ใช้ PROJECT_FACTS_TH.md ตรวจความหมายของหลักฐานเดิม]

### 4.4 การวิเคราะห์ผล

[ผู้เขียนเติมทั้งข้อผิดพลาด FP และ FN เปรียบเทียบเฉพาะผลที่ใช้ข้อมูลและเงื่อนไขเทียบกันได้ หากไม่มีผลการวัดรายการใดให้ระบุว่ายังไม่มีผล]

## 5 สรุปและการอภิปรายผล

### 5.1 สรุปผลตามวัตถุประสงค์

[ผู้เขียนเติมข้อสรุปที่รองรับด้วยผลในส่วนที่ 4]

### 5.2 อภิปรายผล

[ผู้เขียนเติมเหตุผลที่ผลออกมาเช่นนั้น ความสัมพันธ์กับงานวิจัย และขอบเขตที่ตีความได้]

### 5.3 ข้อจำกัด

[ผู้เขียนเติมอย่างน้อยเรื่องข้อมูลประวัติ ความสามารถตรวจ phishing ใหม่ ขอบเขต URL-only สถานะทดลอง การทดสอบ calibration หลังการปรับโมเดล และข้อจำกัดของคำอธิบายจาก LLM]

### 5.4 ข้อเสนอแนะ

[ผู้เขียนเติมงานต่อยอดที่แก้ข้อจำกัด พร้อมวิธีประเมิน เช่น ชุดทดสอบใหม่ที่แยกเวลาและโดเมน]

### กิตติกรรมประกาศ

[ผู้เขียนเติมรายชื่อและความช่วยเหลือที่เกิดขึ้นจริง ตรวจตำแหน่งหัวข้อนี้ตามแม่แบบก่อนส่ง]
